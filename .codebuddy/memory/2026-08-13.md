# 2026-08-13

## 新增 CSV 一键导入工具 server/import-csv.js
- 功能：把 `data/买入-卖出记录 - Sheet1.csv` 的买入/卖出记录按「代码」批量导入 `data/holdings.json`。
- 用法：`npm run import:csv`（仅匹配现有持仓）、`npm run import:csv:new`（匹配不到自动新建持仓）、`node server/import-csv.js <csv>`（指定文件）。
- 匹配规则：① 精确匹配 CSV 代码 === holdings.code；② 数字归一化兜底（`hk00700`→`700`）。
- 买入→push 到 `purchases[]`（止盈止损沿用持仓值）；卖出→push 到 `sells[]`，按 LIFO 自动算 costPrice/profit/returnRate（参照 server.js applyTransaction）。
- 导入后调用脚本内 syncFromPurchases 重算汇总字段（cost/buyQuantity/avgCost/lastBuyPrice/status）。
- **幂等**：以 (代码, 操作, 日期, 数量, 价格) 为唯一键，重复导入自动跳过。已修复日期格式不一致导致的幂等失效：CSV 日期 `2026/5/5` 需归一化为 `2026-05-05`（补前导零）再比较，否则与 holdings 里的 `2026-07-28` 匹配不上。
- package.json 已加 `import:csv`、`import:csv:new` 两个脚本；README 新增「一键导入 CSV 买卖记录」章节。
- 已实际导入：海力士(07709) 新增 4 条买入+2 条卖出（跳过 3 条与已有重复的买入）、新建 小米集团-W(1810) 并导入 4 条买入。备份文件 `data/holdings-before-import.json`。

## 排障：看不到交易记录明细
- 现象：导入数据后前端卡片交易明细空白（PurchaseTable 显示「暂无交易记录」），但 `data/holdings.json` 里 purchases/sells 数据完整。
- 根因：**正在运行的常驻服务（`node server/index.js`，旧 PID 25273）是旧代码进程**，其 `withDerived` 不返回 `transactions` 字段（该字段是后来加的，前端 PurchaseTable 依赖 `holding.transactions` 渲染）。旧进程加载的是改前代码，Node ESM 启动时一次性加载，进程运行期间代码改动不生效。curl 验证：API 返回的 holdings 对象里有 purchases/sells 但**缺 transactions**。
- 处理：杀掉旧进程、重启 `node server/index.js`（新 PID 51982，端口 3000），新服务加载最新代码即可返回 transactions。
- 注意：交易明细在卡片内是**折叠**的，需点击卡片标题左侧箭头展开。生产模式下服务托管 `dist/`，若前端有改动需先 `npm run build` 再重启。不要直接改磁盘 data 文件后不重启服务（store 有内存缓存，mtime 变化会触发重读，但**代码改动必须重启进程**）。
