# 股票秘书 — 盈亏计算规则

> 版本：v2.0（新增 手续费 / 分红 / 送转拆股 / 成本法可选 / 历史成本沿用 / 快照与统计口径）
> 关联文档：技术设计.md、需求文档.md、优化建议.md
> 适用范围：持仓盈亏、成本均价、交易记录的所有数值派生
> 实现位置：**`server/derive.js` 是唯一口径实现**（页面录入、CSV 导入、策略判断、统计报表全部走它）

## 1. 交易模型

每只持仓（Holding）维护四个独立的记录数组：

```
Holding
├── purchases[]   // 买入记录
├── sells[]       // 卖出记录
├── dividends[]   // 现金分红记录
└── splits[]      // 送转 / 拆股记录
```

**关键原则**：
1. 卖出不修改任何买入记录；所有买入记录永久保留。
2. **卖出记录里已落盘的成本/盈亏是账本事实**，默认原样沿用（见 §2.3）。

### 1.1 买入记录 `Purchase`

```ts
interface Purchase {
  id: string;
  buyPrice: number;           // 买入单价
  buyQuantity: number;        // 买入数量
  buyTime: string;            // 买入日期 (YYYY-MM-DD)
  fee: number;                // 手续费（本地币种，计入成本）
  targetProfitRate: number;   // 本笔的止盈收益率 (%)
  stopLossRate: number;       // 本笔的止损收益率 (%)
}
```

### 1.2 卖出记录 `Sell`

```ts
interface Sell {
  id: string;
  sellPrice: number;          // 卖出单价
  sellQuantity: number;       // 卖出数量
  sellDate: string;           // 卖出日期 (YYYY-MM-DD)
  fee: number;                // 手续费 / 印花税等（从盈亏中扣除）
  costPrice: number;          // 卖出时的成本均价（按成本法计算，见 §2.2）
  profit: number;             // 该笔卖出实现的盈亏金额
  returnRate: number;         // 该笔卖出实现的收益率(%)
}
```

### 1.3 分红记录 `Dividend`

```ts
interface Dividend {
  id: string;
  date: string;               // 除息 / 到账日期
  amount: number;             // 本次现金分红总额（税前，本地币种）
  fee: number;                // 红利税 / 手续费（可选）
  note: string;               // 备注（如"中期分红"）
}
```

> 口径：分红**不计入持仓成本**，直接计入已实现盈亏。因此分红后持仓均价不变，累计收益增加。

### 1.4 送转 / 拆股 `Split`

```ts
interface Split {
  id: string;
  date: string;               // 生效日期
  ratio: number;              // 每 1 份变成 ratio 份（10送5 → 1.5；1拆2 → 2）
  note: string;
}
```

> 口径：对 `buyTime <= split.date` 的买入批次，数量 ×ratio 且单位成本 ÷ratio → **份额增加、成本总额不变、均价下降**。
> 送转**不追溯改写历史已实现盈亏**（已卖出的部分视为已了结）。

## 2. 成本计算

### 2.1 总买入

```
单笔买入成本 = buyPrice × buyQuantity + fee
单笔单位成本 = 单笔买入成本 / buyQuantity        （手续费按数量摊入）

总买入成本   = Σ(每笔买入成本)      ← 含手续费
总买入数量   = Σ(buyQuantity)       ← 送转后口径
```

### 2.2 卖出成本（成本法可选）

成本法由持仓字段 `costMethod` 决定，可选：

| 值 | 含义 | 卖出时优先取 |
| --- | --- | --- |
| `LIFO`（默认） | 后进先出 | 买入日期最新的剩余批次 |
| `FIFO` | 先进先出 | 买入日期最早的剩余批次 |
| `WAC` | 移动加权平均 | 当前剩余成本 ÷ 剩余数量 |

```
LIFO / FIFO：
    sortedLots = 剩余批次按 buyTime 升序(FIFO) / 降序(LIFO)
    remaining = sellQuantity; totalCost = 0
    for each lot in sortedLots:
        take = min(remaining, lot.remainQty)
        totalCost += take × lot.unitCost      // unitCost 已含手续费
        remaining -= take
    if remaining > 0 → ❌ 卖出数量超过持仓数量，报错且不落盘

WAC：
    unitCost = 剩余成本 / 剩余数量            // 账本金额闭环
    totalCost = unitCost × sellQuantity

costPrice = totalCost / sellQuantity
```

### 2.3 历史成本沿用原则（重要）

- `sells[].costPrice` / `profit` 在**录入那一刻**算出并落盘，之后**默认不再改写**。
- 原因：先卖出、后补录买入（或补录更晚日期的买入）时，若用"当前完整批次池"重算，会算出"卖出了当时还不存在的份额"这种不可能的结果，把真实亏损算成盈利。
- 兜底：若历史值缺失或非法（手工编辑过 JSON），会用当前批次池补算，**不再产生 NaN**。
- 需要按新成本法重算历史时，用显式操作：
  - 页面：持仓卡片「按当前成本法重算历史成本」
  - 接口：`POST /api/holdings/:id/recompute`
  - ⚠️ 该操作会**改写历史卖出成本**，属用户主动行为，执行前建议先备份。

### 2.4 剩余仓位

```
已卖出成本   = Σ(sells[].costPrice × sells[].sellQuantity)
已卖出数量   = Σ(sells[].sellQuantity)

剩余成本     = max(总买入成本 − 已卖出成本, 0)
剩余数量     = max(总买入数量 − 已卖出数量, 0)
剩余均价     = 剩余数量 > 0 ? 剩余成本 / 剩余数量 : 0
仓位(position) = 剩余成本
```

> 剩余成本/数量/均价与明细恒等闭合（`买入 − 已卖出`），不会出现"汇总与明细对不上"。

## 3. 盈亏计算

### 3.1 单笔卖出盈亏

```
卖出利润     = (sellPrice − costPrice) × sellQuantity − fee
卖出收益率   = costPrice > 0 ? (sellPrice − costPrice) / costPrice × 100 : 0
```

### 3.2 汇总指标

#### 当前市值

```
市值 = currentPrice × 剩余数量
```

#### 未实现盈亏（浮动盈亏）

```
未实现盈亏 = (currentPrice − 剩余均价) × 剩余数量
```

#### 已实现盈亏（已卖出部分 + 分红）

```
已实现盈亏 = Σ(sells[].profit) + Σ(dividends[].amount − dividends[].fee)
```

#### 持仓总盈亏

```
持仓盈亏   = 未实现盈亏 + 已实现盈亏
持仓收益率 = 总买入成本 > 0 ? 持仓盈亏 / 总买入成本 × 100 : null
```

> 分母用「总买入成本」（含手续费），因为那才是该持仓的全部投入。

#### 今日盈亏

```
今日盈亏   = (currentPrice − prevClose) × 剩余数量
今日收益率 = prevClose > 0 ? (currentPrice − prevClose) / prevClose × 100 : null
```

> 仅用「剩余数量」；`prevClose <= 0`（异常行情）时置 null，不参与计算。

#### 手续费合计

```
手续费合计 = Σ(买入 fee) + Σ(卖出 fee)
```

## 4. 交易流水展示

### 4.1 合并排序

四类记录合并为一条时间线，按日期倒序排列：

```
transactions = [
  { ...purchase, type: 'BUY'      },
  { ...sell,     type: 'SELL'     },
  { ...dividend, type: 'DIVIDEND' },
  { ...split,    type: 'SPLIT'    },
].sort(by 日期 DESC)
```

### 4.2 字段覆盖规则

| 字段 | 买入 | 卖出 | 分红 | 送转 |
| --- | --- | --- | --- | --- |
| 日期 | `buyTime` | `sellDate` | `date` | `date` |
| 价格 | `buyPrice` | `sellPrice` | — | `×ratio` |
| 数量 | `buyQuantity` | `sellQuantity` | — | — |
| 手续费 | `fee` | `fee` | `fee`（红利税） | — |
| 成本 | `buyPrice×qty + fee` | `costPrice×qty` | 0 | — |
| 市值/成交额 | `现价×qty` | `sellPrice×qty` | 分红金额 | — |
| **收益/收益率** | `-- / --` | `profit / returnRate` | `amount − fee` | `-- / --` |
| 止盈% / 止损% | 有 | `—` | `—` | `—` |
| 操作 | 修改 / 删除 | 删除 | 删除 | 删除 |

## 5. 汇总卡展示

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| 市值 / 数量 | `现价×剩余数量` / 剩余数量 | |
| 成本 / 现价 | `剩余成本` / `currentPrice` | |
| 今日收益/收益率 | `(现价−昨收)×剩余数量` / `(现价−昨收)÷昨收×100` | 仅未卖出份额 |
| 持仓收益/收益率 | `未实现+已实现` / `总盈亏÷总买入成本×100` | 已实现含分红 |
| 止盈% / 止损% | 买入记录成本加权均值（显式设置优先） | 不随卖出变化 |
| 已实现收益 | `Σ卖出盈亏 + 分红净额` | |
| 累计分红 / 手续费合计 | `Σ(分红−红利税)` / `Σ买卖手续费` | |
| 成本法 / 峰值收益率 | `costMethod` / `peakReturnRate` | 峰值用于移动止盈 |

## 6. 策略阈值口径

| 触发 | 条件 |
| --- | --- |
| 止盈 SELL/PROFIT | `当前收益率 >= 止盈% − nearThresholdPct` |
| 移动止盈 SELL/TRAILING | 启用后：`当前收益率 <= 峰值收益率 − trailingStopPct` |
| 止损 SELL/STOPLOSS | 任一买入记录：`(现价−买入价)/买入价 <= −该笔止损% + nearThresholdPct` |
| 补仓 BUY | `现价 <= 补仓价` 或 `较最近买入价跌幅 >= 补仓降幅 − nearThresholdPct` |
| 日涨跌告警 | `当日涨跌幅` 超过 `dailyRiseAlertPct` / `dailyDropAlertPct`（每品种每日最多一次） |

**防御规则**（避免错误提醒）：
- `currentPrice` 缺失或 `<= 0`（停牌、行情源异常）→ 全部不触发
- `|当日涨跌幅| > notify.maxDailyMovePct`（默认 50%）→ 视为错价，跳过本轮
- 剩余数量为 0（已清仓）→ 不触发
- 同一触发态在 `notify.cooldownSeconds` 内不重复推送

## 7. 快照与统计口径

### 7.1 每日快照 `data/snapshots.json`

调度器在 `schedule.snapshotAt`（默认 16:10，北京时间）后每个交易日记录一条：

```
总成本 / 总市值 / 持仓收益 / 未实现 / 累计已实现 / 今日收益（均折人民币）
+ 在仓品种数 + 分币种明细 + 当时使用的汇率
```

- 幂等：同一日期重复检测为**覆盖**（upsert），不会产生重复行。
- 去重状态记录在 `data/daily-state.json`，进程重启不会重复推送日报。
- 收益趋势接口（`/api/trend`）中，**同一日期以快照为准**，无快照的日期用 K 线重放补齐。

### 7.2 收益归因 `/api/stats/closed`

| 指标 | 口径 |
| --- | --- |
| 累计已实现收益 | 全部标的 Σ(已实现)，折人民币 |
| 已清仓笔数 / 胜率 | 剩余数量为 0 的标的；`胜率 = 盈利笔数 / 已清仓笔数` |
| 盈亏比 | `总盈利 / |总亏损|` |
| 平均持有天数 | 首次买入日 → 最后卖出日的天数均值 |
| 年度已实现收益 | 按卖出/分红日期归年，折人民币 |
| 最佳 / 最差 Top3 | 按已清仓标的的已实现盈亏（人民币）排序 |

> 汇率口径：历史点统一按**当前配置汇率**折算（v1 约定，不做逐日汇率回溯）。

## 8. 数据流

```
用户操作
  │
  ├─ 添加买入记录 (POST /purchases)
  │   └─ push → purchases[]
  │
  ├─ 修改买入记录 (PATCH /purchases/:id)
  │   └─ 更新单价/数量/日期/手续费/止盈止损
  │
  ├─ 删除买入记录 (DELETE /purchases/:id)
  │
  ├─ 交易 (POST /transactions)   type = BUY / SELL / DIVIDEND / SPLIT
  │   ├─ BUY      → push purchases[]（fee 计入成本）
  │   ├─ SELL     → 先校验数量，再按成本法算 costPrice → push sells[]
  │   ├─ DIVIDEND → push dividends[]（计入已实现）
  │   └─ SPLIT    → push splits[]（份额折算，均价下降）
  │   └─ 全部 → syncFromPurchases() 落盘汇总字段
  │
  ├─ 修改交易 (PATCH /transactions/:id)   手续费 / 分红金额 / 送转比例
  ├─ 删除交易 (DELETE /transactions/:id)
  └─ 重算历史成本 (POST /recompute)       显式操作，会改写历史

后台定时刷新行情
  ├─ 更新 currentPrice / prevClose（含停牌与错价防御）
  ├─ updatePeak() → 维护移动止盈峰值收益率
  ├─ 到点写每日快照 + 推送收盘日报
  └─ syncFromPurchases() → 重新计算剩余成本/数量/均价（持久化）

页面请求 GET /api/holdings
  └─ withDerived() → transactions + 全部汇总指标（运行时计算，与落盘字段同源）
```
