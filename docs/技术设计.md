## 1. 总体架构

采用**单进程定时轮询**架构，适合个人轻量部署：

```
┌─────────────────────────────────────────────┐
│                主调度器 (Scheduler)            │
│   定时触发：抓取 → 判断 → 推送                  │
└───────────┬───────────────┬─────────────────┘
            │               │
   ┌────────▼──────┐  ┌─────▼──────────┐
   │  行情模块      │  │  策略引擎       │
   │ PriceProvider │  │ StrategyEngine │
   │  - A股        │  │  - 止盈(卖)     │
   │  - 港股       │  │  - 补仓(买)     │
   │  - 美股       │  │  - 状态机/去重  │
   └────────┬──────┘  └─────┬──────────┘
            │               │
   ┌────────▼──────┐  ┌─────▼──────────┐
   │  持仓存储      │  │  飞书推送       │
   │ HoldingsStore │  │ FeishuNotifier │
   │ (JSON/DB)     │  │ (Webhook)      │
   └───────────────┘  └────────────────┘
            │
   ┌────────▼──────┐
   │  配置 Config   │  (行情源/Webhook/频率/阈值)
   └───────────────┘
```

## 2. 技术选型（建议）

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Node.js (JavaScript, ES Module) | 轻量、内置 fetch/crypto、易常驻部署 |
| 配置 | YAML / JSON | 易手改，无需编译 |
| 存储 | 本地 JSON 文件（v1）→ SQLite（v2） | 个人数据量小，零运维 |
| 行情 | 第三方 REST API（如新浪/腾讯财经、Yahoo Finance、ETF 数据接口） | 免费、无需复杂 SDK |
| 推送 | 飞书自定义机器人 Webhook | 需求指定 |
| 定时 | Node-cron / Python schedule / 系统 cron | 简单可靠 |

> 本项目 Demo 仓库已有 `SQLite-demo`、`SSE` 等参考，可复用其存储/通知思路。

## 3. 数据模型

### 3.1 持仓记录 `Holding`

```ts
interface Holding {
  id: string;                 // 唯一标识
  name: string;               // 股票/基金名称
  code: string;               // 行情代码（用于抓取）
  status: '持有' | '已卖出';
  region: '港股' | '美股' | 'A股';
  type: '股票' | '股票型基金' | '债券型基金' | '货币型基金' | 'ETF';

  // 快照（基准日 7/5）
  snapshotDate: string;       // 基准日, e.g. '2025-07-05'
  snapshotProfit: number;     // 截止基准日收益(金额)
  snapshotReturnRate: number; // 截止基准日收益率(%)

  // 持仓与成本
  position: number;           // 仓位(金额/占比)
  profit: number;             // 持仓盈亏(金额)
  cost: number;               // 总成本
  buyTime: string;            // 首次买入时间
  buyPrice: number;           // 首次买入价
  buyQuantity: number;        // 首次买入数量
  lastBuyPrice: number;       // 最近一次购买价格

  // 策略阈值
  targetProfitRate: number;   // 预期止盈收益率(%)
  refillDropRate: number;     // 补仓降幅(%)
  refillPrice: number;        // 补仓价格

  nextStrategy: string;       // 下阶段策略(备注)

  // 运行时（非手填）
  currentPrice?: number;      // 实时价(抓取填充)
  lastUpdated?: string;       // 行情更新时间
  triggerState?: TriggerState;// 触发状态(见 3.3)
}
```

### 3.2 配置 `Config`

```ts
interface Config {
  schedule: {
    intervalSeconds: 20;            // 交易时段刷新频率
    offHoursIntervalSeconds: 300;   // 非交易时段降频（分钟级）
  };
  feishu: { webhook: string; secret?: string }; // secret 可选，见 §4.3
  providers: {
    'A股': { type: 'tencent'; baseUrl: 'https://qt.gtimg.cn/q=' };   // 免Key, 批量
    '港股': { type: 'tencent'; baseUrl: 'https://qt.gtimg.cn/q=' };  // 免Key, 批量
    '美股': { type: 'tencent'; baseUrl: 'https://qt.gtimg.cn/q=' };  // 腾讯财经同样覆盖美股(代码前缀 us)
  };
  notify: {
    cooldownSeconds: number;                  // 同一品种冷却时长(建议 >= intervalSeconds)
    nearThresholdPct: number;                 // "快达到"的接近度(%)
  };
}
```

> **20 秒高频刷新注意（限流）**：免费行情 API 通常有 QPS / 日额度限制，20 秒一轮（3 次/分钟）且持仓多时易触发限流或 IP 封禁。应对：
> - 同一市场**批量抓取**（一次请求取多只代码），而非逐只请求。
> - 失败即降级沿用上次成功价，并记录 `lastUpdated` 便于识别陈旧数据。
> - 非交易时段可降低频率（见 §8）。

### 3.3 触发状态机 `TriggerState`

```ts
type TriggerState = 'IDLE' | 'TRIGGERED_BUY' | 'TRIGGERED_SELL' | 'NOTIFIED';
```

状态流转：
- `IDLE` → 价格进入买点 → `TRIGGERED_BUY` → 推送成功 → `NOTIFIED`
- `IDLE` → 价格进入卖点 → `TRIGGERED_SELL` → 推送成功 → `NOTIFIED`
- 价格离开区间 → 复位 `IDLE`（解除冷却，下次可再提醒）

## 4. 核心模块设计

### 4.1 行情模块 `PriceProvider`

```ts
interface PriceProvider {
  region: Region;
  fetchPrice(code: string): Promise<number>; // 返回实时价
}
```

- 统一使用腾讯财经适配器，按 `code` 前缀自动路由（A股 `sh/sz`、港股 `hk`、美股 `us`），**一次批量请求**取回所有持仓价格。
- 统一异常：抓取失败抛 `PriceFetchError`，由调度器捕获并跳过该品种、记录日志。
- 缓存：成功价写入 `currentPrice` + `lastUpdated`，失败可沿用上次成功价（降级）。

### 4.2 策略引擎 `StrategyEngine`

输入：一条 `Holding`（含 `currentPrice`）。

**卖点（止盈）判断（基于成本）：**
```
avgCostPrice   = cost / buyQuantity          // 买入均价 = 总成本 / 总数量
currentReturnRate = (currentPrice - avgCostPrice) / avgCostPrice * 100
if currentReturnRate >= targetProfitRate - nearThresholdPct  → 接近/达到止盈
```
> 已确认：止盈收益率以**成本**为基准（买入均价），非基准日快照收益。

**买点（补仓）判断：**
```
dropRate = (lastBuyPrice - currentPrice) / lastBuyPrice * 100
if currentPrice <= refillPrice OR dropRate >= refillDropRate - nearThresholdPct → 接近/达到补仓
```

**去重 / 冷却：**
- 仅当 `triggerState === 'IDLE'` 且处于冷却窗口外才推送。
- 推送后置 `NOTIFIED`，记录 `notifiedAt`；价格复位后回到 `IDLE`。

### 4.3 飞书推送 `FeishuNotifier`

```ts
sendCard(payload: {
  name: string; region: Region; type: string;
  trigger: 'BUY' | 'SELL';
  currentPrice: number;
  advice: string;        // 买点/卖点建议
  summary: string;       // 收益/亏损概览
}): Promise<void>
```

- 使用飞书「自定义机器人」Webhook，消息采用 **interactive 富文本卡片**（`msg_type: interactive`），含带色标题（买点绿色 / 卖点红色）、字段布局与操作建议，比纯文本更直观。
- **`secret` 已确认启用**（长期运行更安全）：
  - 不配：直接 POST 即可，URL 泄露则任何人可冒用发消息。
  - 配置：请求需带 `timestamp` + `sign`，`sign = base64(HMAC-SHA256(timestamp + "\n" + secret))`，飞书校验签名且 timestamp 须在 3600 秒内；即便 URL 泄露也无法伪造消息。
- 失败重试 2–3 次，超次记录错误日志，不阻塞主循环。

## 5. 主调度流程

```
loop every 20s (intervalSeconds):
  holdings = store.loadAll()
  for h in holdings where status == '持有':
    try:
      price = provider.fetchPrice(h.code)
      h.currentPrice = price; h.lastUpdated = now
    catch: log warning; continue

    result = engine.evaluate(h)   // 返回 BUY/SELL/NONE + advice
    if result != NONE and not inCooldown(h):
      notifier.sendCard(buildPayload(h, result))
      h.triggerState = NOTIFIED; h.notifiedAt = now
    else if price left band:
      h.triggerState = IDLE

  store.saveAll(holdings)
```

## 6. API / 接口设计

### 内部函数级
| 模块 | 方法 | 说明 |
| --- | --- | --- |
| HoldingsStore | `loadHoldings()` / `saveHoldings()` | 内存缓存 + 串行写盘 |
| PriceProvider | `fetchPrices(codes)` | 批量取实时价 |
| StrategyEngine | `evaluate(h)` | 返回触发结果与建议 |
| FeishuNotifier | `sendCard(payload)` | 发送飞书卡片 |
| Scheduler | `startScheduler()` | 启动定时循环 |
| Server | `startServer()` | 启动 HTTP 服务 |

### 对外 REST（前端页面使用）
- `GET /api/holdings`：持仓列表（含派生字段 收益率 / 跌幅 / 均价）
- `POST /api/holdings`：新建持仓（买入建仓）
- `POST /api/holdings/:id/transactions`：追加交易 `{type:'BUY'|'SELL', price, quantity, date?}`，自动重算成本、数量、最近买入价、状态，并复位触发态

> 调度器与 HTTP 接口**共用同一份内存持仓**（`store.js` 缓存），写盘串行化，避免并发覆盖。

对外仅暴露：
- `GET /` 与 `/api/*`（本地 `127.0.0.1:3000`，未在公网暴露）
- 飞书 Webhook（出站）

## 8. 部署方式

- 本地：`npm start`（Node.js 进程常驻，20 秒一轮）。
- 轻量云：容器化常驻运行；**非交易时段**（如 A股 15:00–9:30、美股盘后）可动态降频至分钟级，降低限流风险。
- 行情抓取按市场**批量请求**，避免逐只高频打 API。
- **非交易时段自动降频**：每个 tick 按持仓所属市场判断交易时段（A股 9:30–11:30/13:00–15:00、港股 9:30–12:00/13:00–16:00、美股 9:30–16:00 ET，均剔除周末），有任一市场开盘用 `intervalSeconds`，否则降到 `offHoursIntervalSeconds`（默认 300 秒）。
- 配置与持仓**不入库**，以文件形式随项目存放，便于手动维护。
