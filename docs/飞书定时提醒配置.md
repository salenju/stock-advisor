# 提醒配置：页面通知 + 飞书定时推送

> 关联：`README.md` 的「提醒」、`docs/GitHub私有仓库令牌配置.md`（数据仓库）、`docs/GitHub一键建仓与OAuth授权.md`
> 代码位置：`web/src/core/alerts.js`（判定口径，两端共用）、`web/src/composables/useNotify.js`（浏览器通知）、
> `scripts/notify-cron.mjs`（Actions 定时检查）、`scripts/feishu.mjs`（签名与卡片）、`.github/workflows/notify.yml`

---

## 1. 两种提醒，能力互补

| | **页面通知**（方式一） | **飞书定时推送**（方式二） |
| --- | --- | --- |
| 谁在盯着 | 浏览器标签页 | GitHub Actions（云端定时任务） |
| 页面要开着吗 | **要** | 不要 |
| 手机能收到吗 | 装了 PWA 才行，且页面在后台 | 能，飞书 App 推送 |
| 需要配置什么 | 点一下「允许通知」 | 一次性的 Secrets / Variables 配置 |
| 适合 | 盘中我在看盘 | 上班/开会/不在电脑前 |
| 判定口径 | 完全相同（`core/alerts.js` 一份代码） | 同左 |

两者可以同时开，去重规则各自独立，互不干扰。

判定范围：止盈（成本加权）、移动止盈（峰值回撤）、止损（按笔）、补仓（降幅/目标价）、日涨告警、日跌告警。

## 2. 方式一：页面通知（30 秒）

1. 打开站点，页面顶部会出现「**开启桌面通知**」提示条，点「**开启**」→ 浏览器弹权限框选「允许」
   （也可以走「🗄 数据 → 提醒 → 允许通知」）
2. 点「**发送测试通知**」确认能看到系统通知
3. 之后每次刷新行情都会检查一遍阈值：命中 → 页面顶部列出来 + 弹系统通知

规则与限制：

- **同一标的 + 同一种提醒，当天只通知一次**（记录在 `localStorage` 的 `stock-advisor:notify-sent`，跨天自动清空）
- 一次最多弹 3 条，多出来的合并成一条「还有 N 条提醒」
- 只在页面开着时有效；标签页被浏览器休眠/系统勿扰模式下可能收不到
- **iOS 必须先把网页「添加到主屏幕」，再从主屏图标打开**，才支持 Web 通知（Safari 标签页里不行）
- 关掉开关（数据面板里的复选框）后再改数据不会推送，也不会占用当天的去重名额

## 3. 方式二：GitHub Actions → 飞书

### 3.1 前置条件

- 数据已经在**你自己的私有仓库**里（页面「🗄 数据 → ☁️ GitHub 私有仓库 → 上传到云端」）
- 有一个自己的 GitHub 仓库副本（fork 本仓库即可，公开仓库的 Actions 免费）

### 3.2 第一步：建飞书自定义机器人

1. 打开目标群 → 群设置 → **群机器人** → **添加机器人** → **自定义机器人**
2. 复制 Webhook 地址（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）
3. 安全设置二选一（建议都开）：
   - **签名校验**：复制密钥，后面填 `FEISHU_SECRET`
   - **自定义关键词**：填 `股票秘书`（提醒卡片里一定含有这个词）
   - IP 白名单不适合本方案（Actions 出口 IP 不固定）

### 3.3 第二步：配置 Secrets / Variables

在自己仓库的 `Settings → Secrets and variables → Actions` 里填：

**Variables（普通变量）**

| 名称 | 必填 | 说明 |
| --- | --- | --- |
| `NOTIFY_ENABLED` | ✅ | 填 `true`。**不填则整个 workflow 直接跳过**（避免没配好就每分钟报红） |
| `DATA_OWNER` | ✅ | 数据仓库 owner，如 `your-name` |
| `DATA_REPO` | ✅ | 数据仓库名，如 `stock-data` |
| `DATA_PATH` | ⬜ | 数据文件路径，默认 `stock-advisor-data.json` |
| `DATA_BRANCH` | ⬜ | 分支，默认 `main` |
| `NOTIFY_COOLDOWN_HOURS` | ⬜ | 同一提醒的冷却小时数，默认 `12` |
| `NOTIFY_DRY_RUN` | ⬜ | 填 `true` 时只打印卡片不发消息、不写状态（首次接入强烈建议先跑这个） |

**Secrets（密钥）**

| 名称 | 必填 | 说明 |
| --- | --- | --- |
| `DATA_TOKEN` | ✅ | 能读写数据仓库的令牌（Fine-grained：该仓库 `Contents: Read and write`，与页面里用的是同一个） |
| `FEISHU_WEBHOOK` | ✅ | 机器人 Webhook 地址 |
| `FEISHU_SECRET` | ⬜ | 开了「签名校验」就必填 |
| `DATA_PASSPHRASE` | ⬜ | 页面里填过加密口令就必填，否则脚本解不开密文 |

> ⚠️ Webhook 和令牌**只放 Secrets**，永远不要写进 `notify.yml` 或任何被提交的文件（旧版本曾经因此泄露过，见 `docs/优化建议.md`）。

### 3.4 第三步：启用并试跑

1. 打开仓库的 **Actions** 页签（fork 仓库的定时任务默认是禁用的，必须手动点一次启用）
2. 左侧选「**定时提醒（飞书）**」→ 右侧 **Run workflow**
3. 先保持 `NOTIFY_DRY_RUN=true` 跑一次：日志里会打印命中的卡片 JSON，飞书群不会收到消息
4. 确认无误后把 `NOTIFY_DRY_RUN` 改回空（或 `false`），再跑一次 → 飞书应该收到卡片

### 3.5 定时策略

`.github/workflows/notify.yml` 默认：

```yaml
schedule:
  - cron: '*/15 1-8 * * 1-5'   # UTC 01:00–08:59 = 北京 09:00–16:59，A股/港股时段
```

- GitHub 的 cron 用 **UTC**，且**最小间隔 5 分钟**，高峰期实际触发可能延迟 5–15 分钟
- 需要美股时段就再加一行：`- cron: '*/15 13-21 * * 1-5'`（北京 21:00–05:59）
- 只想收盘后总结一次就换成：`- cron: '10 8 * * 1-5'`（北京 16:10）
- 公开仓库 Actions 免费；**私有仓库**按分钟计费，本 job 每次约 15–30 秒，15 分钟一次约 200–250 分钟/月（免费额度 2000 分钟）
- `notify.yml` 只在**默认分支**上按计划运行；改了 cron 记得合并到默认分支

## 4. 冷却与状态：`notify-state.json`

Actions 每次运行都是全新环境，没有内存可继承，所以冷却状态写在**数据仓库里**，与数据文件同目录：

```json
{
  "updatedAt": "2026-11-07T08:30:00.000Z",
  "sent": {
    "a1b2c3|PROFIT": "2026-11-07T08:30:00.000Z",
    "a1b2c3|DAILY_DROP": "2026-11-07T05:15:00.000Z"
  }
}
```

- 键 = `持仓id|提醒类型`，与页面通知的去重键完全一致
- **只在真的发出消息后**才写入，所以「没发出去」不会占用冷却名额
- 只保留最近 7 天的记录（自动清理，不会无限膨胀）
- 第一次运行时文件不存在属正常，脚本会自动创建
- 想立刻重新收到同一条提醒：删掉该文件的对应键，或把 `NOTIFY_COOLDOWN_HOURS` 调小

删除这个文件是安全的（等于遗忘冷却历史）。

## 5. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Actions 里看不到定时运行的记录 | `NOTIFY_ENABLED` 没设成 `true`，或本分支不是默认分支 | 去 Variables 补上；确认 workflow 在默认分支 |
| fork 后一直没有按计划运行 | **fork 仓库的定时任务默认禁用** | Actions 页签点一次「启用」 |
| `✖ 缺少环境变量 DATA_TOKEN` | Secret 名字拼错，或建在了 Environment 里而非仓库 Secrets | 按 3.3 的表名逐字核对 |
| `✖ 数据文件不存在` | 还没在页面「上传到云端」 | 先在页面点一次上传 |
| `解密失败：加密口令不正确` | `DATA_PASSPHRASE` 与页面里的口令不一致 | 填入页面里那串口令（密钥里存，别放变量里） |
| 飞书返回 `code 19021` | 机器人开了签名校验，但没给 `FEISHU_SECRET`（或时钟偏差 > 1h） | 填 `FEISHU_SECRET`；确认本机/Actions 时钟正常 |
| 飞书返回 `code 19024` / 关键词不匹配 | 机器人安全设置用了「自定义关键词」但消息里没有 | 关键词设为 `股票秘书`，或改用签名校验 |
| 收到消息但内容为空 / 全是 0 | 行情接口临时不可用 | 看日志里的「行情成功 x / 失败 y」，重跑一次；A股午休时段价格不更新属正常 |
| 同一条提醒收到好几次 | `notify-state.json` 写不进去（令牌没有写权限） | 令牌补 `Contents: Read and write` |
| 股价很便宜却被跳过 | 单日波动超过 `maxDailyMovePct`（默认 50%）被当成错价 | 在数据面板/设置里调大该阈值 |

日志在 Actions 运行详情里，每个阶段都有 `→` / `⚠️` 前缀，能直接看出卡在哪一步。

## 6. 建议做法

- **两条都开**：页面上给即时反馈，飞书兜住"人不在电脑前"
- 飞书只推「同一提醒 12 小时内一次」；追求更安静就调到 `24`
- 数据仓库的令牌与 Webhook 定期更换；飞书群里的机器人被误删时重新建一个并更新 Secret
- 加密口令建议填：即使仓库被误设为公开，Actions 之外的任何人也读不到持仓（Actions 靠 `DATA_PASSPHRASE` 解密）
