# 股票秘书 — 功能优化方案

> 版本：v1.0
> 日期：2026-09-10
> 基于：当前代码库全量走读（server/ 14 文件、web/src/ 12 组件、docs/、test/）
> 目标：在现有基础上，按优先级梳理可优化项，保持「低维护、自动提醒、一目了然」的定位

---

## 0. 现状盘点（已有能力）

| 模块 | 现状 |
| --- | --- |
| 持仓管理 | 多市场（A股/港股/美股）股票+场外基金，多次买入/卖出记录，LIFO 成本核算，CSV 幂等导入 |
| 行情 | 腾讯行情（批量/免Key）+ 东财基金净值，交易时段 20s / 非交易时段 300s 自适应降频 |
| 策略 | 止盈（成本加权）、止损（单笔触发）、补仓（降幅/目标价）、日涨跌告警 |
| 通知 | 飞书 interactive 卡片 + HMAC 签名，冷却去重（默认 1h） |
| 前端 | Vue3 + Vite + Tailwind，概览卡（分币种小计）、收益趋势图、标签过滤、增删改弹窗、暗色模式 |
| 存储 | `data/holdings.json` 单文件，内存缓存 + mtime 失效 + 串行写盘 |
| 测试 | node:test 28 项（行情解析/币种/趋势/CSV/接口） |

整体架构清晰、测试意识好。以下建议按 **P0（安全与正确性）→ P1（高价值功能）→ P2（锦上添花）** 排列。

## 1. P0 — 必须优先处理的问题

### 1.1 个人数据与密钥已进 Git 仓库（安全风险）

- **现状**：项目是 git 仓库且已关联 `origin/main`，但 `.gitignore` 只忽略了 `node_modules/ dist/ *.log .DS_Store`。也就是说：
  - `config.json` 里的**真实飞书 webhook 地址**已进入 git 历史；
  - `data/holdings.json` 里的**全部个人投资明细**（易方达蓝筹各笔买入价/数量等）也在仓库中。
  一旦推到公开远端（或未来开源），等于把个人资产清单公开。
- **建议**：
  1. `.gitignore` 追加 `config.json`、`data/*.json`、`data/*.csv`；
  2. 新增 `config.example.json`（占位符版本）和 `data/holdings.example.json` 入库作模板；
  3. 若远端已含敏感历史，用 `git filter-repo` 清理后强推（个人仓库操作前先备份 bundle）；
  4. 飞书 webhook 在飞书群设置里**重新生成**，作废旧地址。
- **涉及文件**：`.gitignore`、`config.json`

### 1.2 HTTP 服务无鉴权且监听 0.0.0.0

- **现状**：`config.json` 中 `server.host: "0.0.0.0"`，所有 REST 接口（增删改持仓、导入 CSV）无任何鉴权，同一局域网内任何人都能改你的投资数据。
- **建议**（三选一，按场景）：
  - 仅本机用 → host 改回 `127.0.0.1`（最简单）；
  - 局域网用 → 增加简单 Bearer Token：`config.authToken` + 中间件校验 `Authorization` 头，前端启动时从 localStorage 带上；
  - 公网用 → 必须加鉴权 + HTTPS 反代（nginx/caddy）。
- **涉及文件**：`server/server.js`（`startServer` 增加校验中间件）、`config.json`

### 1.3 `deriveSell` 的 `??` 兜底失效（潜在计算 bug）

- **现状**：`server/server.js` 第 130-131 行：

  ```js
  const profit = Number(s.profit) ?? ((sellPrice - costPrice) * qty);
  const returnRate = Number(s.returnRate) ?? (costPrice > 0 ? ... : 0);
  ```

  `Number(undefined)` 的结果是 `NaN` 而不是 `undefined`，`NaN ?? x` 返回 `NaN`（`??` 只兜 null/undefined）。一旦某条卖出记录缺 `profit` 字段（手工编辑 JSON、旧数据迁移），该笔盈亏会变成 `NaN` 并污染汇总。
- **建议**：改为

  ```js
  const profit = Number.isFinite(Number(s.profit)) ? Number(s.profit) : (sellPrice - costPrice) * qty;
  const returnRate = Number.isFinite(Number(s.returnRate)) ? Number(s.returnRate)
    : (costPrice > 0 ? ((sellPrice - costPrice) / costPrice) * 100 : 0);
  ```

  并补一条单测：缺 profit 字段的 sell 记录派生结果正确。
- **涉及文件**：`server/server.js`、`test/api.test.js`

### 1.4 交易日历缺失：节假日误轮询 + 停牌/异常价格无防御

- **现状**：`scheduler.js` 的 `isMarketOpen` 只判周末+固定时段，不识别法定节假日。后果：
  - 节假日仍按交易时段频率轮询（浪费，但无害）；
  - 更严重的是**停牌或行情源返回 0/异常值时无防御**：`q.price == null` 会跳过，但 `price = 0` 会被当作真实价格写入 `currentPrice`，触发错误的止损/补仓判断并推送错误提醒。
- **建议**：
  1. `evaluate` 与调度循环对 `price <= 0` 直接跳过（一行防御，收益最大）；
  2. 接入交易日历：可内置每年 A股/港股休市日数组（每年手动维护一次，`config.holidays`），或用腾讯行情返回的成交量字段（停牌成交量为 0）判断；
  3. 行情连续 N 次失败时推送一条「行情源异常」告警，避免静默失联。
- **涉及文件**：`server/scheduler.js`、`server/strategy.js`

### 1.5 数据无自动备份

- **现状**：`data/` 下都是手工备份（`holdings-0724备份.json` 等），命名随意、无保留策略；README 也只提示「建议导入前先备份」。
- **建议**：`store.saveHoldings` 里每次写盘前轮转备份：复制当前文件到 `data/backups/holdings-YYYYMMDD-HHmm.json`，按日去重、保留最近 30 份（清理逻辑顺手写掉）。数据是这类工具的全部价值，自动备份性价比极高。
- **涉及文件**：`server/store.js`

## 2. P1 — 高价值功能优化

### 2.1 交易成本与分红送转（投资记账的核心缺口）

- **现状**：买入成本 = 价格×数量，**不含佣金/印花税/过户费**；卖出同样；完全没有**分红、送股、转股、拆股**记录类型。长期持有下（尤其港股美股高分红标的、A股送转），账面收益率会系统性失真。
- **建议**：
  1. 每笔买入/卖出增加可选字段 `fee`（手续费），成本与盈亏计算统一加上；
  2. 新增交易类型 `DIVIDEND`（现金分红：金额、日期）与 `SPLIT`（送转：比例、日期）。分红计入已实现收益；送转按比例调整历史买入数量（或按"折算成本法"只调整数量不动成本，口径写入 `docs/盈亏计算规则.md`）；
  3. 前端 TransactionModal 增加对应表单分支；CSV 导入支持「分红」列。
- **涉及文件**：`server/server.js`（applyTransaction/withDerived）、`web/src/components/TransactionModal.vue`、`server/import-csv-core.js`、`docs/盈亏计算规则.md`

### 2.2 已清仓收益归因报表（个人复盘最有用的功能）

- **现状**：卖出记录都在，但没有复盘视角——看不到自己「历史战绩」。
- **建议**：新增 `GET /api/stats/closed` + 前端「已清仓」页签：
  - 每笔已清仓交易：品种、买入均价、卖出价、持有天数、盈亏金额、收益率；
  - 汇总：胜率、平均持有天数、平均盈利/平均亏损比、最佳/最差交易 Top3、累计已实现收益（分年度）。
  数据全在本地，纯计算，无外部依赖，是投入产出比最高的新功能。
- **涉及文件**：新增 `server/stats.js`、`server/server.js`（路由）、新增 `web/src/components/ClosedPositionsPanel.vue`

### 2.3 每日收盘快照落盘（趋势与日报的基础设施）

- **现状**：收益趋势每次请求都「实时拉 K 线 + 逐日重放」，依赖第三方接口可用性；没有历史快照，出不了月度/年度报表。
- **建议**：调度器在每日各市场收盘后（如 16:30 检测当日已有收盘价）追加写一条 `data/snapshots.json`：`{date, marketValue, holdingProfit, realizedProfit, perCurrency:{...}}`。之后：
  - 趋势优先读快照，K 线只补当天缺口（更快更稳）；
  - 免费获得月度/年度收益统计与「年度收益报表」页面；
  - 历史点汇率失真问题（v1 约定用当前汇率折算）可顺带升级为快照时点汇率。
- **涉及文件**：`server/scheduler.js`、新增 `server/snapshot.js`、`server/trend.js`

### 2.4 汇率自动更新

- **现状**：USD=7.0 / HKD=0.9 写死在配置，注释称「汇率变化不大」——但 2024-2026 人民币波动并不小，固定汇率会让港美股折算收益偏差数个百分点。
- **建议**：每日一次调用免费汇率接口（如 `https://api.frankfurter.app/latest?from=USD&to=CNY` 或腾讯行情里的汇率），成功则写回 `config.fx.rates` 并带 `updatedAt`；失败沿用旧值并在界面标注「汇率更新于 X 日前」。保留环境变量覆盖能力。
- **涉及文件**：新增 `server/provider/fx-live.js`、`server/scheduler.js`

### 2.5 成本核算方法可选（LIFO → LIFO/FIFO/移动加权）

- **现状**：卖出固定按 LIFO 计算成本均价。国内常见口径是移动加权平均，券商 APP 也有用 FIFO 展示的；LIFO 在连续加仓场景容易把成本算得偏高。
- **建议**：持仓级字段 `costMethod: 'LIFO' | 'FIFO' | 'WAC'`（默认沿用 LIFO 保证兼容），`applyTransaction` 按方法计算 `costPrice`。注意 LIFO 卖出后历史买入记录不动（现有设计），FIFO 同理；WAC 则直接用当时均价。口径变化在 `docs/盈亏计算规则.md` 中写明。
- **涉及文件**：`server/server.js`（applyTransaction）、`docs/盈亏计算规则.md`、`test/api.test.js`

### 2.6 策略增强：移动止盈（trailing stop）

- **现状**：止盈是固定比例，行情冲高回落时「到过 25% 又跌回 10%」不会触发任何提醒，白白错过。
- **建议**：持仓级可选字段 `trailingStopPct`（如 8%）：调度器持续记录持仓期内最高收益率 `peakReturnRate`（新字段，随行情更新落盘），当 `当前收益率 <= peak - trailingStopPct` 时触发 `SELL(TRAILING)` 提醒。卡片文案给出「峰值 X% → 当前 Y%，回撤 Z%」。
- **涉及文件**：`server/strategy.js`、`server/scheduler.js`、`server/notifier.js`、`web/src/components/HoldingCard.vue`（阈值编辑入口）

### 2.7 前端组合视图补全

- **现状**：概览只有金额卡片 + 收益趋势折线，缺组合结构视角；持仓渐多后无排序、无归档。
- **建议**：
  1. **组合分布饼图**（按市场/类型/单品种市值，人民币口径），ECharts 按需引入即可；
  2. **表格排序**：点表头按收益率/今日涨跌/市值排序；
  3. **已清仓归档**：状态「全部卖出」的默认折叠到独立页签（现在混在主列表里靠状态标签区分）；
  4. **收益率热力条**：每行背景色深浅映射收益率，一眼扫出好坏（复用现有红涨绿跌约定）。
- **涉及文件**：`web/src/components/OverviewCards.vue`、`HoldingList.vue`、`HoldingCard.vue`、`App.vue`

### 2.8 每日收盘日报推送

- **现状**：飞书只在触发阈值时推送，没有每日总结。收盘后想知道「今天赚了多少」得自己开页面。
- **建议**：调度器检测各市场收盘后，向飞书推送一条日报卡片：今日总收益（分币种）、Top3 盈亏贡献、当前持仓收益概览、今日触发的提醒回顾。与 2.3 的快照机制天然配套。
- **涉及文件**：`server/scheduler.js`、`server/notifier.js`（新增日报卡片模板）

## 3. P2 — 锦上添花

### 3.1 数据导出

- 一键导出交易明细 / 已清仓报表为 CSV（复用现有 CSV 解析器思路反向生成），方便报税或存档。
- **涉及文件**：`server/server.js`（`GET /api/export?scope=trades|closed`）、前端导出按钮。

### 3.2 通知渠道扩展 + 告警偏好

- PRD 非功能需求已写「扩展邮件/微信」。可抽 `notifier.js` 为多通道分发（飞书/企业微信 webhook/邮件 SMTP/Server酱），按 `config.notify.channels` 配置；
- 每持仓可勾选「仅提醒买点/仅卖点/全要」，减少无关打扰。

### 3.3 前端轮询 → SSE 推送（可选）

- 现状前端每 REFRESH_MS 拉全量 `/api/holdings`，行情其实由后端调度器每 20s 更新，两边节奏不同步（倒计时归零时行情可能还没刷新，看到的是旧价）。用 SSE（`text/event-stream`）由后端在每轮 tick 后推送增量，前端去掉轮询与倒计时，数据永远新鲜。改动集中在 `server/server.js` + `useHoldings.js`，Node 内置 http 完全支持。

### 3.4 部署与可观测性

- 增加 `GET /api/health`（返回行情源最近成功率、上次 tick 时间、持仓数），配合 PM2 或 Docker（写个 Dockerfile + docker-compose， volumes 挂 `data/`）一键部署；
- 日志落盘：目前只有 console，建议按天写 `logs/app-YYYYMMDD.log`（tick 结果、推送成败、接口错误），满足 PRD 的日志需求，排查「为什么没提醒」时非常有用。

### 3.5 场外基金净值时效标注

- 东财净值当日晚间才更新，白天看到的 currentPrice 是昨日净值，"今日收益"对基金实际是「昨日收益」。建议 API 返回 `priceAsOf`（净值日期），前端对基金行显示「净值 9/9」角标，避免误读。

### 3.6 代码质量：拆分与去重

- `server/server.js` 已 22KB/623 行，职责过载（静态托管 + 12 个 REST 路由 + 3 套派生计算）。建议：
  1. 派生计算（`withDerived`/`derivePurchase`/`deriveSell`/`syncFromPurchases`）抽到 `server/derive.js`——目前**同样的聚合逻辑在 `strategy.js` 的 `agg()` 里又实现了一遍**，三处并存，改口径要改三处，是未来 bug 温床；
  2. REST 路由抽 `server/routes/`，静态托管抽 `server/static.js`；
  3. 日期比较统一工具：现在 `String(b.buyTime).localeCompare(...)` 裸排在 4 处使用，一旦日期格式混入 `ISO` 带时间戳与 `YYYY-MM-DD`，排序即错（现有数据已同时存在两种 region 格式的先例）。
- 测试补位：`strategy.js` 的 nearPct 边界、`withDerived` 的 NaN 防御、卖出超量的 400 分支。
