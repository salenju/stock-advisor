# 股票秘书 — 需求文档（PRD）

> 版本：v1.0
> 来源：项目 `README.md` 原始需求
> 适用范围：个人持仓管理 + 实时价格监控 + 飞书机器人提醒

---

## 1. 产品背景

用户需要一款轻量的「股票秘书」工具，用于：

1. **集中记录**自己在不同市场（港股 / 美股 / A股）的股票与基金持仓。
2. **实时跟踪**持仓品种的当前价格，并基于预设策略判断买点 / 卖点。
3. **主动提醒**：当价格接近买入（补仓）或卖出（止盈）阈值时，通过**飞书机器人**推送提醒，并附带明确的操作建议（买点或卖点）。

目标用户为个人投资者，强调「低维护、自动提醒、一目了然」。

---

## 2. 功能需求

### 2.1 持仓记录（核心数据）

系统需支持维护以下持仓字段，每条记录代表一个持有或已清仓的品种：

| 字段 | 说明 | 类型 / 枚举 |
| --- | --- | --- |
| 名称 | 股票 / 基金名称 | 文本 |
| 状态 | 当前持仓状态 | 持有 / 已卖出 |
| 地区 | 交易市场 | 港股 / 美股 / A股 |
| 仓位 | 当前持仓占比或金额 | 数值 |
| 持仓盈亏 | 浮动盈亏金额 | 数值 |
| 类型 | 品种分类 | 股票 / 股票型基金 / 债券型基金 / 货币型基金 / ETF |
| 截止7/5收益 | 基准日（7/5）累计收益金额 | 数值 |
| 截止7/5收益率 | 基准日（7/5）累计收益率 | 百分比 |
| 预期止盈收益率 | 触发卖出提醒的目标收益率 | 百分比 |
| 买入时间 | 首次建仓时间 | 日期 |
| 买入价格 | 首次买入价格 | 数值 |
| 买入数量 | 首次买入数量 | 数值 |
| 成本 | 总投入成本 | 数值 |
| 最近一次购买价格 | 最近一次加仓价格 | 数值 |
| 补仓降幅 | 相对最近价，触发补仓的下跌幅度 | 百分比 |
| 下阶段策略 | 用户备注的后续操作计划 | 文本 |
| 补仓价格 | 触发补仓的目标价格 | 数值 |

> 说明：「截止7/5」为采集需求时的基准快照日，系统中应抽象为「基准日快照」，避免与当前实时数据混淆。

### 2.2 实时价格获取

- 根据每个持仓品种的「地区 + 名称/代码」，从对应行情源获取**当前价格**。
- 需覆盖三种市场：港股、美股、A股。
- 行情数据应可定时刷新（如每 N 分钟一次），并记录最近一次更新时间。

### 2.3 阈值判断与策略提醒

系统需基于以下逻辑自动判断是否需要提醒：

1. **卖点提醒（止盈）**：当实时价格相对成本 / 基准价的收益率 **接近或达到**「预期止盈收益率」时，触发卖出提醒。
2. **买点提醒（补仓）**：当实时价格相对「最近一次购买价格」**下跌达到「补仓降幅」**，或接近「补仓价格」时，触发买入 / 补仓提醒。
3. 提醒内容需**同时给出明确的买点或卖点建议**（例如：当前价 X，建议补仓价 Y，可买入 Z 股）。

### 2.4 飞书机器人推送

- 当任一持仓触发买点 / 卖点条件时，调用**飞书自定义机器人 Webhook** 发送消息。
- 消息内容包含：品种名称、地区、当前价、触发类型（买 / 卖）、建议操作、收益 / 亏损概览。
- 提醒应去重 / 收敛，避免在阈值区间内**重复刷屏**（如仅在状态首次进入触发区时发送，或设置冷却时间）。

---

## 3. 非功能性需求

| 维度 | 要求 |
| --- | --- |
| 部署 | 个人使用，运行在本地或轻量云服务器 / 定时任务即可 |
| 配置 | 行情源、飞书 Webhook、刷新频率、阈值参数应可配置 |
| 可维护性 | 数据结构清晰，便于手动增删改持仓 |
| 日志 | 记录每次价格抓取、触发判断、推送结果，便于排查 |
| 扩展性 | 后续可加入更多市场、更多提醒渠道（邮件 / 微信） |

---

## 4. 用户场景

**场景 A — 补仓提醒**
> 用户持有某港股，最近买入价 10.0，补仓降幅设为 10%（即补仓价 9.0）。当行情跌至 9.0 附近，飞书收到：「【港股】XXX 已跌至 9.05，接近补仓价 9.0，建议补仓，下阶段策略：分批买入。」

**场景 B — 止盈提醒**
> 用户持有某 ETF，成本对应收益率基准，预期止盈收益率 20%。当实时收益率接近 20%，飞书收到：「【A股】XXX 当前收益率 19.6%，接近预期止盈 20%，建议择机卖出。」

---

## 5. 范围与边界

- **包含**：持仓管理、行情抓取、阈值判断、飞书推送。
- **暂不包含（v1.0）**：自动下单交易、组合回测、多用户、历史K线图表、税务计算。
- 行情 API 的可用性依赖第三方，需考虑失败重试与降级。

---

## 6. 验收标准

1. 可手动录入 / 编辑全部 2.1 中的持仓字段。
2. 系统能按地区获取持仓实时价格，并与记录中的基准数据对照。
3. 当价格进入买点 / 卖点区间时，飞书机器人能在合理时延内收到结构化的提醒消息。
4. 提醒不重复刷屏，有清晰的冷却 / 去重机制。
5. 所有配置（Webhook、频率、阈值）可通过配置文件调整，无需改代码。
